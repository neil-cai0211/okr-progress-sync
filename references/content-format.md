# 内容格式规范

## 四段模板

组员 OKR 进展报告的固定结构，也是 Leader 周报的对应结构：

1. **本周进展** — 这周做完了什么，量化结果优先。
2. **发现的问题** — 遇到了什么阻塞、什么 bug、什么卡点。
3. **风险同步与资源支持** — 有什么风险预警，需要 Leader 或其他部门给什么支持。
4. **下周进度计划** — 下周打算做什么。

组员写的内容不一定严格按这四段标题来，可能混在一起。需要 AI 帮忙拆分归类。

## 回填格式

### 单个组员块

Leader 进展里，每个组员是一个独立块，块内四段一一对应：

```
@姓名
本周进展：[组员本周进展的内容]
发现的问题：[组员遇到的问题]
风险同步与资源支持：[组员提到的风险和需要的支持]
下周进度计划：[组员下周的计划]
```

四段标签固定为上面这四个标准名；如需简写，可对应为：进展 / 问题 / 资源支持 / 计划。

### 多个组员块的排列

同一条 Leader KR 下有多个组员时，**一人一块**，块按本次处理先后（即填写顺序）从上到下排列，新块接在已有内容后面，不改动任何人已写的内容：

```
@组员A
本周进展：1234
发现的问题：1222
风险同步与资源支持：123445
下周进度计划：1345

@组员B
本周进展：12342
发现的问题：12222
风险同步与资源支持：1234452
下周进度计划：13452
```

- 不要把多人的进展先汇总成一段、再把问题汇总成一段；必须保持"一个人一段、段内四段齐全"。
- 块与块之间留一行空行分隔，保证清晰完整。
- 某组员某一段没写内容，该段保留标签、内容写「无」，不要省略标签。

### @人写法

用 `simple` 风格的 SemiPlainContent：
```json
{
  "text": "@王颖颖\n本周进展：调研问卷回收50W份...\n...",
  "mention": ["ou_wangyingying_open_id"]
}
```

- `text` 里写 `@姓名` 作为可见文字。
- `mention` 数组里传对应人的 open_id，飞书会自动渲染成真正的 @ 提及。
- 不要只在 text 里打 `@名字` 而不传 mention 数组，那样只是纯文本，不是真的 @。

## 内容处理原则

### 1. 保留原意，不编造
- 组员写了什么就放什么，不要自己加内容、加数据。
- 组员没写的段落，留空或写「无」，不要瞎补。

### 2. 适当精简润色
- 组员写的很长、很口语化，可以压缩成要点式。
- 但不能改变事实、数字和结论。
- 数字必须原样保留，不能四舍五入或改写。

### 3. 分段对齐
- 组员写的一段流水账，要尝试拆成四段。
- 拆不出来的，都放到「本周进展」里，其他段写「无」。
- 个别句子拿不准属于哪段时，保守归到「本周进展」。
- 若整条进展无法判断对应 Leader 的哪条 KR，或段落归属存在实质歧义、影响回填位置，**停下来向用户提问**，不要自行猜着填。

### 4. 追加不覆盖、顺序排列
- 永远在 Leader 已有进展后面新增一条记录（一人一条），不修改、不删除已有块。
- 写入前先 `+progress-list` 看一下，确认这个组员这周还没写过。
- 新增块排在已有块之后，同批多个组员按处理顺序依次追加。
- 重复写了会导致周报里出现两条同一个人的进展。

## 写入前检查清单

写入 Leader KR 之前，过一遍这几条：

- [ ] @ 的人 open_id 对不对？
- [ ] 是否一人一块、块内四段标签齐全？组员没写的段是不是写「无」而不是省略？
- [ ] 数字和事实是不是和组员原文一致？
- [ ] 目标 KR ID 对不对？别写错 KR 了。
- [ ] 这条 KR 下这周已经有这个组员的记录了吗？有就不重复写。
- [ ] 新块是不是追加在已有内容后面、没有覆盖或改动别人的块？
